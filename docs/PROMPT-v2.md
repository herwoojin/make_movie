## A. 프로젝트 규칙 추가분 (`AGENTS.md` 맨 아래에 붙여넣기)

```markdown
## v2 추가 규칙 (2026-09 기능 보강)

### 상호작용 모델이 바뀌었다
편집의 기본 단위는 "자동 감지 제안"이 아니라 **단어 칩**이다.
사용자는 화면에 나열된 단어 칩의 ⊗를 눌러 그 단어를 영상에서 직접 잘라낸다.
자동 감지(무음·추임새)는 **칩을 미리 지워두는 보조 수단**일 뿐, 주된 편집 방식이 아니다.
이 전제를 깨는 설계를 하지 마라.

### 화면 구조
- 편집은 2단계 파이프라인이다: `1단계 자동편집` → `2단계 자막·영상 편집`
- 1단계는 그 자체로 완결된다. 2단계 없이 끝낼 수 있어야 한다.
- 2단계는 여러 1단계(음성 자동편집 / 해외 영상 번역)가 공유하는 공용 화면이다.
- 좌측 메뉴는 도구 목록이고, 각 도구는 자기 라우트를 가진다.

### 실행 계층
이 앱은 2계층이다.
- A계층(브라우저): 편집 UI와 미디어 처리 전부. **사이드카 없이도 완결 동작해야 한다.**
- B계층(사이드카): 127.0.0.1:47600 로컬 도우미. 유튜브 다운로드, 네이티브 ffmpeg,
  로컬 번역/TTS, 임의 폴더 저장. **선택 설치.**

규칙:
1. 사이드카 유무는 `useSidecar()` 훅 하나로만 판단한다. 곳곳에 fetch를 흩뿌리지 마라.
2. 사이드카가 없을 때 에러 팝업을 띄우지 마라. 해당 버튼을 비활성화하고
   "로컬 도우미를 설치하면 쓸 수 있어요" 안내를 조용히 붙인다.
3. 사이드카가 필요한 기능은 UI에 미리 배지로 표시한다. 눌러보고 나서 알게 하지 마라.
4. 사이드카 주소를 0.0.0.0 으로 바인딩하는 코드는 절대 작성하지 마라.

### 시간 계산 순서 (버그 최다 발생 지점)
원본시간 → [EDL 적용] → [배속 적용] → 출력시간
이 순서를 고정한다. `lib/core/edl.ts`의 sourceToOutput / outputToSource는
반드시 배속을 인자로 받아야 한다. 순서를 바꾸면 자막이 전부 어긋난다.

### 데이터 모델
- 편집의 단위는 `EditClip`이다. v1의 `SubtitleCue`는 SRT 입출력 중간 표현으로만 쓴다.
  두 테이블을 동시에 유지보수하지 마라.
- `TranscriptWord.deleted`는 실제 삭제가 아니라 플래그다. 원본 배열은 보존한다.
- Dexie 스키마를 바꿀 때는 version(2).upgrade()를 반드시 함께 작성한다.

### 성능
- 20분 영상이면 단어 칩이 3,000개를 넘는다. 클립 목록은 가상 스크롤 필수.
- 칩 하나 지울 때 전체 목록을 리렌더하지 마라. 해당 클립만 리렌더한다.
```

이 기능이 v2의 핵심입니다. 3개로 쪼개서 진행하세요.

### B-1. 데이터 모델과 순수 로직

```
PRD-v2.md의 F-01과 6장(ERD 증분)을 읽고, 단어 칩 편집의 데이터 계층을 만들어 주세요.
UI는 아직 만들지 마세요.

작업 범위:
1. src/lib/storage/db.ts
   - EditClip 인터페이스 추가 (PRD-v2 F-01의 타입 정의 그대로)
   - TranscriptWord에 clipId, deleted, deletedAt 필드 추가
   - Dexie version(2) 스키마 + upgrade() 작성
     editClips: 'id, projectId, [projectId+idx], enabled'
   - 기존 v1 데이터가 있으면 SubtitleCue → EditClip으로 옮기는 마이그레이션

2. src/lib/core/clips.ts  (전부 순수 함수, DOM 의존 금지)
   - buildClipsFromWords(words, opts): EditClip[]
       단어 배열을 클립(자막 한 줄)으로 묶는다.
       분할 기준: 문장부호 / 0.7초 이상 간격 / maxChars 초과
   - deleteWord(state, wordId): 단어를 deleted=true로 표시하고
       그 클립의 captionText를 남은 단어로 재생성
   - restoreWord(state, wordId)
   - clipToEdlSegments(clip, words): EdlSegment[]
       삭제되지 않은 단어 구간만 남긴 세그먼트 배열.
       인접 단어 간격이 150ms 미만이면 하나로 병합한다.
   - recalcClipDuration(clip, words): number

3. src/lib/core/edl.ts 수정 ⚠️ 중요
   - sourceToOutput(sourceMs, edl, speedMap) 으로 시그니처 변경
   - outputToSource도 동일하게
   - 적용 순서는 반드시 EDL → 배속. 순서를 바꾸지 마세요.

4. Vitest 테스트 (같은 커밋에)
   - 단어 하나 삭제 → 클립 길이가 그 단어 길이만큼 줄어든다
   - 클립의 모든 단어 삭제 → enabled=false 가 된다
   - 인접 단어 연속 삭제 → EDL 세그먼트가 하나로 병합된다
   - 간격 150ms 이상인 단어 두 개 삭제 → 세그먼트가 두 개로 분리된다
   - 삭제 후 복원 → 원래 상태와 정확히 같아진다
   - captionEdited=true인 클립은 단어를 지워도 captionText가 덮어써지지 않는다
   - 배속 1.5배 + 단어 삭제가 같이 걸린 경우의 sourceToOutput 값

완료 조건:
- npm run typecheck 통과
- 위 7개 테스트 전부 통과
- lib/core 커버리지 90% 이상

주의:
- 단어를 지울 때 앞뒤 30ms 패딩을 적용하세요 (TRD 4.3장 규칙).
- 패딩 적용 후 구간 길이가 0 이하가 되면 그 삭제는 무시합니다.
```

```

   - [1단계 결과 가져오기]: 최근 1단계 프로젝트 목록에서 선택

      글자수 비례로 추정한다 — 이 경우 칩 삭제 정밀도가 낮다고 안내)
   - 번역 도구에서 인계

6. 좌측 하단 편집 프로젝트 패널
   파일명 / "N개 자막 클립" / [1단계 결과 가져오기] [영상 + SRT 열기]
   / 화면 비율(원본·유튜브 16:9·쇼츠 9:16)

완료 조건:
- 1단계에서 자동편집 후 2단계로 넘어가면 클립 목록이 채워져 있다
- 넘어갈 때 재인코딩이 일어나지 않는다 (즉시 전환된다)
- SRT를 직접 열어도 클립 목록이 만들어진다

### 시간 계산 버그가 났을 때

```

5. 클립 경계에서 반올림이 누적되고 있지 않은가

먼저 어긋난 값을 콘솔에 찍어서 실제 수치를 보여주고,
원인을 특정한 다음 고쳐 주세요. 추측으로 수정하지 마세요.
