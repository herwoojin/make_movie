## 0. 먼저 짚어야 할 전제 — 실행 환경이 다르다

캡쳐를 분석한 결과, 비교 대상인 **두팔 스튜디오는 Windows 설치형 데스크톱 앱**이다. 근거는 다음과 같다.

| 캡쳐에서 관찰된 것 | 의미 |
|---|---|
| `C:\Users\sunju\AppData\Local\DoopalStudio\Qwen3TTS\recordings\voice-...wav` | 로컬 파일시스템 임의 경로 read/write |
| `C:\Users\sunju\Videos\ForeignSubtitleOutput` + `찾기` / `결과 폴더` | 네이티브 폴더 선택 다이얼로그, 탐색기 열기 |
| `Qwen3-TTS 0.6B · CPU`, `Qwen3 4B · PC 내 처리`, `번역 엔진 설치` | 로컬 LLM/TTS 런타임 설치·실행 |
| 유튜브 URL → `1080p 이하` → `다운로드` | yt-dlp류 네이티브 다운로더 |
| `Microphone(Yeti X)` 등 장치명 노출 | 오디오 장치 열거 |
| `v263 · PAID PILOT`, `© 2026 기계왕 곽두팔` | 버전 배포되는 설치형 빌드 |

반면 우리가 만든 것은 `http://localhost:3000/editor/...` 로 도는 **브라우저 웹앱**이다.

**이 차이를 무시하고 기능만 베끼면 개발 중반에 반드시 막힌다.** 유튜브 다운로드, 임의 폴더 저장, 4B급 로컬 번역 모델 — 이 셋은 순수 브라우저 샌드박스 안에서 해결되지 않는다.

### 그래서 v2의 핵심 결정: **하이브리드 2계층 구조**

```
┌─────────────────────────────────────────────────────────────┐
│  A계층 — 브라우저 (지금 만든 Next.js 웹앱)                    │
│  · 편집 UI 전부, 타임라인, 자막, 모자이크, 렌더링             │
│  · 사이드카가 없어도 "웹 기능만으로" 완결 동작한다             │
└──────────────────────────┬──────────────────────────────────┘
                           │ HTTP (127.0.0.1 전용)
┌──────────────────────────┴──────────────────────────────────┐
│  B계층 — 로컬 도우미(사이드카) · 선택 설치                     │
│  Node 또는 Python 단일 실행파일, 127.0.0.1:47600             │
│  · 유튜브 다운로드 (yt-dlp)                                  │
│  · 네이티브 ffmpeg (브라우저보다 5~10배 빠름)                 │
│  · 로컬 번역 LLM / 로컬 TTS                                  │
│  · 임의 폴더 저장 · 탐색기 열기                               │
└─────────────────────────────────────────────────────────────┘
```

**원칙**: 사이드카는 **있으면 좋은 것**이지 **없으면 안 되는 것**이 아니다. 앱은 사이드카 연결 여부를 감지해서 해당 기능을 켜고 끈다. 이미 `localhost:3000`에서 개발 중이므로 사이드카 추가는 자연스럽다.

## 2. 신규 요구사항 상세

### F-01. 단어 칩 단위 삭제 (최우선) 🔴

#### 왜 중요한가
v1은 "무음 구간을 감지해서 목록으로 제안 → 사용자가 승인"하는 방식이었다. 두팔 스튜디오는 **모든 단어를 칩으로 나열하고, 지우고 싶은 단어의 ⊗를 누르면 그 단어가 영상에서 잘려나간다.**

이 차이는 결정적이다. 제안 목록은 "AI가 고른 것 중에서 고르기"지만, 단어 칩은 **"내가 원하는 아무 단어나 지우기"**다. 추임새("어", "음")뿐 아니라 말실수, 반복 문장, 불필요한 수식어까지 전부 클릭 한 번으로 제거된다. 롱폼 편집자가 실제로 원하는 건 후자다.

#### 캡쳐에서 확인된 UI 구조
```
┌──────────────────────────────────────────────────────────────────┐
│ ☐  [1]  🎬영상편집                                          ▶  ✕ │
│         00:00.0 + 3.1초                                          │
│         ┌─────┐⊗ ┌──────────┐⊗ ┌───────┐⊗ ┌─────────────┐⊗     │
│         │ 네, │   │반갑습니다.│   │기계왕 │   │곽투팔입니다.│       │
│         └─────┘   └──────────┘   └───────┘   └─────────────┘     │
│                                                                   │
│         ⌨ 네, 반갑습니다. 기계왕 곽투팔입니다.                     │
└──────────────────────────────────────────────────────────────────┘
```
- 클립 헤더: 번호 · 소스 배지(`영상편집` / `원어 음성`) · `시작시각 + 길이초` · 재생 ▶ · 클립 삭제 ✕
- 좌측 체크박스: 다중 선택용 (상단 `선택 삭제`와 연동)
- 단어 칩: 단어마다 ⊗ 버튼, 4~8개가 한 줄, 넘치면 자동 줄바꿈
- 하단 자막 입력줄: 남은 단어들로 구성된 최종 자막 텍스트, 직접 수정 가능

#### 사용자 스토리
- F-01-1. 사용자는 클립 안의 단어 칩에서 ⊗를 눌러 그 단어를 영상·음성에서 함께 제거한다.
- F-01-2. 삭제된 단어는 즉시 자막 텍스트 줄에서도 사라지고, 클립 길이가 줄어든다.
- F-01-3. 사용자는 `되돌리기`로 방금 지운 단어를 복원한다.
- F-01-4. 사용자는 체크박스로 여러 클립을 선택하고 `선택 삭제`로 통째로 제거한다.
- F-01-5. 사용자는 ▶로 해당 클립만 미리듣는다. 삭제 반영 후의 소리로 들린다.
- F-01-6. 사용자는 하단 자막 줄을 직접 고쳐 쓴다. (이때 영상은 안 잘린다 — 자막 텍스트만 바뀜)
- F-01-7. 사용자는 한 클립의 모든 단어를 지우면 그 클립이 자동으로 비활성(취소선) 처리되는 것을 본다.

#### 기술 요구사항
- STT의 **단어 단위 타임스탬프가 필수 전제**다. 이게 없으면 이 UI 자체가 성립하지 않는다.
- 단어 칩 삭제 → `CutSuggestion`이 아니라 **즉시 EDL 반영**. 단, 원본 데이터는 유지해서 되돌리기 가능.
- 삭제 경계 처리: 단어 앞뒤 **30ms 패딩**, 인접 단어와 간격 150ms 미만이면 자연 연결을 위해 확장. (v1 TRD 4.3장 규칙 재사용)
- 오디오 컷 경계 **5ms 크로스페이드** 필수. 없으면 "뚝뚝" 끊기는 소리가 난다.
- 칩 렌더 성능: 20분 영상이면 단어가 3,000개 넘는다. **클립 단위 가상 스크롤** 필수.

#### 데이터 모델 추가
```ts
/** ERD의 TranscriptWord에 필드 추가 */
```

### F-02. 1단계 → 2단계 파이프라인 🔴

#### 구조
두팔 스튜디오는 편집을 **명시적인 2단계**로 나눈다. 우측 상단에 `1 자동편집  2 자막·영상 편집` 스텝 표시가 항상 떠 있다.

```
[1단계 · 음성 자동편집]                    [2단계 · 자막과 영상 편집]
 영상 넣기                                  1단계 결과 가져오기
 → 무음/추임새 자동 감지            ──▶     → 단어 칩 편집
 → 컷 적용                                  → 자막 서식 / 배속
 → "테스트영상_자동편집.mp4" 저장             → 화면 비율
                                            → 완성 영상 내보내기
```

중요한 점: **1단계는 그 자체로 완결된다.** 1단계만 쓰고 끝내도 되고(자동편집된 mp4가 나옴), 2단계로 넘겨서 자막까지 붙여도 된다. 해외 영상 번역 도구도 똑같이 "1단계 한국어 자막 생성 → 2단계 자막·영상 편집"으로 2단계를 공유한다.

#### 사용자 스토리
- F-02-1. 사용자는 1단계에서 자동편집을 마치고 `2단계로 보내기`를 눌러 편집을 이어간다.
- F-02-2. 사용자는 2단계에서 `1단계 결과 가져오기`로 직전 1단계 산출물을 불러온다.
- F-02-3. 사용자는 2단계에서 `영상 + SRT 열기`로 **외부에서 만든 영상과 자막 파일**을 직접 넣어 시작한다. (1단계 없이 2단계만 쓰는 경로)
- F-02-4. 사용자는 화면 우측 상단 스텝 표시로 현재 위치를 항상 확인하고, 클릭해서 단계 간 이동한다.
- F-02-5. 사용자는 좌측 하단 `편집 프로젝트` 패널에서 현재 파일명과 `N개 자막 클립`을 확인한다.

#### 화면 구조 변경 (v1 대비)
v1은 `/editor/[projectId]` 단일 화면이었다. v2는 **도구별 라우트 + 공유 2단계**로 바꾼다.

| `/` | 랜딩 · 도구 목록 | 좌측 메뉴 구조로 재편 |
| `/auto-edit` | **1단계 · 음성 자동편집** | 무음/추임새 자동 컷 |
| `/editor/[projectId]` | **2단계 · 자막·영상 편집** | 단어 칩 · 서식 · 배속 · 내보내기 |

### F-03. 서식 적용 범위 (선택 클립 / 영상 전체) 🔴

#### 요구사항
우측 서식 패널 최상단에 **적용 범위 토글**이 있다.

```
서식 적용 범위
┌──────────┬──────────┐
│ 선택 클립 │ 영상 전체 │      ← 두 개 중 하나 활성
└──────────┴──────────┘
1개 클립 선택 · 1번          ← 현재 선택 상태 안내
```

- `영상 전체`: 폰트/크기/색/테두리/배경 변경이 **모든 클립**에 적용 → `SubtitleStyle` 갱신
- `선택 클립`: 체크한 클립에만 적용 → 해당 클립들의 `styleOverrideId` 생성/갱신
- 선택된 클립이 0개인데 `선택 클립` 모드면 → 서식 컨트롤 비활성 + "클립을 먼저 선택하세요" 안내

#### 서식 항목 (캡쳐 확인 기준, v1 SubtitleStyle 매핑)
| 캡쳐 항목 | 필드 | 기본값 |
|---|---|---|
| 화면 비율: 원본/16:9/9:16 | `Project.aspectMode` | `original` |
| 글자 (폰트 드롭다운) | `fontFamily` | `Pretendard` |
| 크기 (숫자 스피너) | `fontSize` | `36` |
| B / I 토글 | `fontWeight` / `italic` | `700` / `false` |
| 글자색 (A 아이콘 + 컬러픽커) | `color` | `#FFFFFF` |
| 글자 테두리: `테두리 사용` + 색 + 두께 | `outlineEnabled` / `outlineColor` / `outlineWidth` | `true` / `#000000` / `2.0` |
| 배경: `배경 사용` + 색 | `bgEnabled` / `bgColor` | `true` / `#000000` |
| 배경 불투명도 (%) | `bgOpacity` | `0.72` |

> **v1 ERD 보강**: `SubtitleStyle`에 `italic: boolean`, `outlineEnabled: boolean`, `bgEnabled: boolean` 3개 필드를 추가한다. v1에는 색과 두께만 있고 on/off 스위치가 없었다.

### F-04. 화면 비율 전환 (편집 중) 🟡

v1은 내보내기 프리셋으로만 다뤘다. 두팔 스튜디오는 **편집 중에 비율을 바꾸면 미리보기가 즉시 바뀐다.** 두 곳에 컨트롤이 있다.
- 좌측 하단 `편집 프로젝트` 패널: `원본` / `유튜브 16:9` / `쇼츠 9:16`
- 우측 서식 패널: `원본` / `16:9` / `9:16`

둘은 같은 프로젝트 레벨 설정이다. (한쪽을 바꾸면 다른 쪽도 따라가야 한다.)

#### 사용자 스토리
- F-04-1. 사용자는 세로 영상을 `유튜브 16:9`로 바꿔 좌우에 배경이 채워진 모습을 즉시 확인한다.
- F-04-2. 사용자는 가로 영상을 `쇼츠 9:16`으로 바꾸고, **화면 안에서 보여줄 영역을 드래그로 조정**한다.
- F-04-3. 사용자는 채움 방식을 고른다: `블러 배경` / `단색 배경` / `잘라내기(crop)`
- F-04-4. 자막 크기는 비율 변경 시 **자동으로 재계산**된다. (1080 기준 상대 크기)

#### 기술 노트
- 비율 변경은 **렌더 시점의 캔버스 변환**일 뿐, 원본은 건드리지 않는다.
- 9:16 크롭 오프셋은 `Project.reframe = { x: 0~1, y: 0~1, scale: number }`로 저장.
- 블러 배경: 원본을 캔버스 전체에 `cover`로 그린 뒤 `filter: blur(40px)` → 그 위에 원본을 `contain`으로 얹는다.

### F-05. 배속 탭 🔴

`자막 서식` 옆에 `배속` 탭이 있다. 완전 누락된 기능이다.

#### 사용자 스토리
- F-05-1. 사용자는 선택한 클립의 재생 속도를 0.5× ~ 2.0×로 조절한다.
- F-05-2. 사용자는 `영상 전체` 범위로 전체 배속을 한 번에 건다.
- F-05-3. 사용자는 배속이 걸린 클립에 표시(`1.5×` 배지)를 보고 구분한다.
- F-05-4. 사용자는 **음정 유지(pitch preservation)** 를 켜고 끈다. 끄면 목소리가 높아진다.
- F-05-5. 배속 변경 시 해당 클립의 자막 타이밍이 자동으로 재계산된다.

#### 기술 노트
- 프리셋: `0.5 / 0.75 / 1.0 / 1.25 / 1.5 / 1.75 / 2.0` + 직접 입력
- 비디오: WebCodecs 경로에서 프레임 타임스탬프를 `ts / speed`로 재계산. 2배속이면 프레임을 절반 버리는 게 아니라 타임스탬프를 조정한다.
- 오디오 음정 유지: ffmpeg `atempo` 필터(0.5~2.0 범위는 한 번에 가능). WebCodecs 경로에서는 **간이 WSOLA/phase-vocoder를 직접 구현해야 하므로** 1차 구현에서는 ffmpeg 폴백으로 넘기는 것을 권장.
- ⚠️ 배속과 단어 삭제가 겹치면 시간 계산이 복잡해진다. **적용 순서를 EDL 적용 → 배속 적용으로 고정**하고, `sourceToOutput()` 함수에 배속을 반영해야 한다. 여기가 v2에서 가장 버그 나기 쉬운 지점이다.

### F-06. 영상에 소리 입히기 (더빙) 🔴

#### 사용자 스토리
- F-06-1. 사용자는 영상을 올리고 **별도 오디오 파일**(mp3/wav)을 얹는다.
- F-06-2. 사용자는 기존 오디오를 `완전 교체` / `배경으로 남기기(볼륨 %)` 중에 고른다.
- F-06-3. 사용자는 오디오 시작 지점을 드래그로 맞춘다(싱크 조정, ±ms).
- F-06-4. 사용자는 `내 목소리 TTS`에서 만든 음성을 바로 이 화면으로 가져온다.
- F-06-5. 사용자는 배경음악을 넣고, **말하는 구간에서 자동으로 볼륨을 낮추는**(더킹) 옵션을 켠다.
- F-06-6. 사용자는 페이드 인/아웃 길이를 설정한다.

#### 기술 노트
- 오디오 믹싱은 Web Audio `OfflineAudioContext`로 처리 → 최종 PCM을 인코더에 넘긴다.
- 더킹: 원본 오디오의 RMS 엔벨로프를 계산(무음 감지 코드 재사용) → 발화 구간에서 BGM 게인을 -12dB, 어택 100ms / 릴리즈 300ms.

### F-07. 해외 영상 한국어 자막 (번역) 🟡 → 정식 기능으로 승격

v1에서는 P3 "선택 기능" 한 줄이었다. 캡쳐를 보면 **독립 화면을 가진 주력 기능**이다.

#### 사용자 스토리
- F-07-1. 사용자는 유튜브 URL을 넣고 화질을 골라 영상을 내려받는다. *(사이드카 필요)*
- F-07-2. 사용자는 이미 가진 영상 파일을 `영상 선택`으로 직접 넣는다. *(사이드카 없어도 됨)*
- F-07-3. 사용자는 인식 언어(`자동 감지` 또는 지정), Whisper 모델 크기(`tiny/base/small/medium`), 번역 말투(`원문 말투 유지` / `친근하게` / `격식체` / `구어체`)를 고른다.
- F-07-4. 사용자는 **용어 지정**란에 고유명사 대응표를 넣는다. 예: `Sunburst=선버스트, fidelity=정확도`
- F-07-5. 사용자는 번역 방식을 고른다: `빠르게(문장별 즉시)` / `정밀(번역 후 전체 재검수)`
- F-07-6. 사용자는 원어·한국어가 나란히 나오는 표에서 번역을 직접 고친다.
- F-07-7. 사용자는 `자막 MP4 저장`으로 자막이 구워진 영상을 받거나, `2단계`로 넘겨 서식을 꾸민다.
- F-07-8. 사용자는 작업 `경과 시간`을 확인한다. (8분짜리 영상이 8분 걸린다 — 오래 걸린다는 걸 알아야 한다)

#### 번역 엔진 어댑터 (v1 SttAdapter와 같은 패턴)
```ts
interface TranslateAdapter {
  id: 'local-llm' | 'gemini' | 'deepl' | 'openai';
  displayName: string;
  requiresApiKey: boolean;
  requiresSidecar: boolean;
  isAvailable(): Promise<boolean>;
  translate(
    cues: { start: number; end: number; text: string }[],
    opts: {
      sourceLang: string; targetLang: 'ko';
      tone: 'literal' | 'friendly' | 'formal' | 'casual';
      glossary: Record<string, string>;
      mode: 'fast' | 'precise';
      onProgress?: (done: number, total: number) => void;
    }
  ): Promise<{ start: number; end: number; text: string; translated: string }[]>;
}
```

| 어댑터 | 비용 | 품질 | 사이드카 | 비고 |
|---|---|---|---|---|
| `gemini` (BYOK) | 무료 티어 | 높음 | 불필요 | **1차 권장 기본값** |
| `deepl` (BYOK) | 무료 50만자/월 | 매우 높음 | 불필요 | 용어집 API 지원 |
| `local-llm` | 무료 | 중상 | **필요** | Qwen3 4B 등, Ollama 경유 |
| `openai` (BYOK) | 유료 | 높음 | 불필요 | |

> **솔직한 판단**: 두팔 스튜디오는 `Qwen3 4B`를 PC에서 직접 돌린다. 브라우저에서 4B 모델(양자화 ~2.5GB)을 WebGPU로 돌리는 것은 이론상 가능하나, 모델 다운로드 시간과 메모리 때문에 실용성이 낮다. **사이드카가 Ollama를 호출하는 방식**이 훨씬 현실적이다. 사이드카가 없으면 BYOK API로 간다.

#### `정밀 · 번역 후 전체 재검수` 방식이란
1차로 문장별 번역 → 2차로 **전체 자막을 한 번에 LLM에 넣어 문맥 일관성 재검수**(인칭·용어·존댓말 통일). 8분 영상에 8분 걸리는 이유가 이 2패스 구조다. 구현 시 2차 패스는 토큰 한도 때문에 **30~50개 큐씩 묶어서** 슬라이딩 윈도우로 처리한다.

### F-08. 내 목소리 TTS 🟡 → 재검토 결과 "사이드카로 가능"

v1에서 나는 "무료·브라우저로는 불가능"이라고 썼다. 캡쳐를 보니 **`Qwen3-TTS 0.6B`를 CPU로 로컬 실행**하고 있다. 0.6B는 양자화하면 400~600MB 수준이라 PC에서 충분히 돈다. **사이드카를 쓰면 가능하다**는 쪽으로 판단을 수정한다.

#### 캡쳐에서 확인된 UI

#### 설계상 핵심 통찰
**감정 표현을 프롬프트로 하지 않는다.** 화면에 `감정 프롬프트 미지원 · 선택한 녹음의 말투를 참조`라고 명시되어 있다. 즉 `차분하게`, `밝게` 같은 감정은 **그 감정으로 미리 녹음해둔 참조 샘플**을 고르는 것이다. 사용자가 감정별로 샘플을 `참조 등록`해두면, 생성 시 그 샘플의 말투를 복제한다.

이건 중요한 구현 지침이다. "감정 프롬프트를 지원하는 TTS 모델을 찾는다"가 아니라, **"감정별 참조 오디오 슬롯을 관리하는 UI를 만든다"** 가 정답이다.

#### 사용자 스토리
- F-08-1. 사용자는 마이크 장치를 목록에서 고른다. *(브라우저 `enumerateDevices()`로 가능)*
- F-08-2. 사용자는 화면에 표시된 **참조 문장 원문**을 읽으며 녹음한다. (48kHz/16bit/모노)
- F-08-3. 사용자는 녹음 대신 **기존 음성 파일**을 올린다.
- F-08-4. 사용자는 녹음을 다시 들어보고 마음에 안 들면 재녹음한다.
- F-08-5. 사용자는 감정 슬롯(`차분하게` 등)을 고르고 `참조 등록`으로 그 감정의 샘플을 저장한다.
- F-08-6. 사용자는 읽을 텍스트를 넣고 `내 목소리로 생성`을 눌러 음성을 만든다.
- F-08-7. 사용자는 결과를 듣고 WAV로 받거나, `영상에 소리 입히기`로 바로 보낸다.

#### 실행 경로별 지원 범위
| 경로 | 음성 복제 | 감정 참조 | 비고 |
|---|---|---|---|
| **사이드카 + 로컬 TTS 모델** | ✅ | ✅ | 두팔 스튜디오와 동일. 1차 목표 |
| 브라우저 내장 `speechSynthesis` | ❌ | ❌ | 무료·즉시. 목소리는 시스템 음성 |
| BYOK 클라우드 TTS | ✅ | 부분 | 유료. 음성 복제 약관 확인 필요 |

> **UI에서 반드시 밝힐 것**: 사이드카 미설치 시 "내 목소리 복제는 로컬 도우미 설치가 필요합니다. 지금은 기본 음성으로만 만들 수 있어요."라고 명확히 안내한다. 되는 척하면 안 된다.

### F-09. 유튜브 URL 다운로드 🔴

v1에서 저작권을 이유로 제외했으나, 실사용 도구로서 필요하다고 판단해 포함한다. 다만 아래를 지킨다.

- 기능 위치: `해외 영상 한국어 자막` 화면 내부 + `유튜브 영상 추출` 독립 도구
- **사이드카 필수** (브라우저에서 유튜브 스트림을 직접 받는 것은 CORS로 불가)
- 화질 선택: `1080p 이하` / `720p 이하` / `최고 화질` / `오디오만`
- 최초 사용 시 1회 안내: *"본인이 권리를 가진 영상이나 이용이 허용된 범위 내에서 사용하세요. 각 플랫폼의 이용약관을 확인하는 것은 사용자 책임입니다."* — 매번 띄우지는 않는다.
- 다운로드 이력은 `최근 저장 결과`에 남긴다.

### F-10. 영상 용량 줄이기 🔴

#### 사용자 스토리
- F-10-1. 사용자는 영상을 올리고 **목표 용량(MB)** 또는 **품질 프리셋**을 고른다.
- F-10-2. 사용자는 예상 결과 용량을 압축 전에 미리 본다.
- F-10-3. 사용자는 원본과 압축본을 나란히 비교한다.
- F-10-4. 사용자는 여러 파일을 한 번에 압축한다.

#### 프리셋
| 프리셋 | 해상도 | CRF | 용도 |
|---|---|---|---|
| 고품질 | 원본 유지 | 20 | 보관용 |
| 표준 | 1080p | 24 | 유튜브 업로드 |
| 가볍게 | 720p | 28 | 메신저 공유 |
| 최대압축 | 480p | 32 | 이메일 첨부 |
| 목표 용량 지정 | 자동 계산 | 자동 | 비트레이트 역산 |

목표 용량 역산: `비트레이트(kbps) = (목표MB × 8192) / 길이(초) - 오디오비트레이트`

### F-11. 저장 위치 · 최근 저장 결과 🔴

두팔 스튜디오는 `저장 폴더`를 지정하고 `결과 폴더`로 탐색기를 연다. 브라우저에서는 3단계로 나뉜다.

| 방식 | 조건 | 동작 |
|---|---|---|
| **사이드카** | 설치됨 | 임의 폴더 지정 + 탐색기 열기. 두팔 스튜디오와 동일 |
| **File System Access API** | Chrome/Edge | 폴더 권한을 한 번 받아두면 그 폴더에 계속 저장 |
| **일반 다운로드** | 모든 브라우저 | 브라우저 기본 다운로드 폴더로 저장 |

#### 최근 저장 결과
```ts
export interface SavedResult {
  id: string;
  kind: 'video' | 'gif' | 'audio' | 'subtitle' | 'image' | 'document';
  toolId: string;              // 'auto-edit' | 'translate' | 'tts' | ...
  fileName: string;
  fileSize: number;
  durationMs?: number;
  opfsPath?: string;           // 브라우저 저장분
  localPath?: string;          // 사이드카 저장분
  thumbnailPath?: string;
  projectId?: string;          // 되돌아가서 재편집할 프로젝트
  createdAt: number;
}
```
- 목록에서 `다시 편집` / `폴더 열기` / `다시 받기` / `삭제`
- 최대 100건 유지, 초과 시 오래된 것부터 정리 안내

### F-12. 자잘하지만 빠지면 티 나는 것들 🔴

| 항목 | 요구사항 |
|---|---|
| **자동 따라가기** | 체크 시 재생헤드가 지나가는 클립으로 목록이 자동 스크롤 + 하이라이트. 사용자가 수동 스크롤하면 일시 해제, 3초 후 재개 |
| **경과 시간** | 모든 장시간 작업에 `경과 00:08:03` 표시. 진행률과 **함께** 보여준다 |
| **선택 삭제** | 체크된 클립 일괄 삭제. 삭제 전 "N개 클립을 지웁니다" 확인 |
| **되돌리기 버튼** | 키보드 Ctrl+Z 외에 **화면 상단에 버튼으로도** 제공 (마우스만 쓰는 사용자용) |
| **클립별 재생 ▶** | 그 클립 구간만 반복 재생. 편집 결과가 반영된 소리로 |
| **상태 바** | 화면 하단에 `준비 완료` / `처리 중...` / `저장 완료 · 경로` |
| **소스 배지** | 클립마다 `영상편집` / `원어 음성` 배지로 출처 구분 |
| **N개 자막 클립** | 프로젝트 패널에 항상 표시 |

## 3. 사이드카(로컬 도우미) 규격

### 기본 원칙
- 주소: `http://127.0.0.1:47600` 고정. 외부 바인딩 금지(`0.0.0.0` 절대 금지).
- 인증: 최초 실행 시 토큰 생성 → 사용자가 웹앱 설정에 붙여넣기. 토큰 없는 요청은 401.
- CORS: `http://localhost:3000` 과 배포 도메인만 허용.
- 웹앱은 시작 시 `GET /health`를 1회 호출해 연결 여부를 판단하고, 실패해도 **조용히 웹 전용 모드로 동작**한다. 에러 팝업을 띄우지 않는다.

### API
```
GET  /health
     → { ok: true, version: "1.0.0",
         features: { ytdlp: true, ffmpeg: true, translate: true, tts: true },
         models: { translate: ["qwen3:4b"], tts: ["qwen3-tts-0.6b"] } }

POST /youtube/download   { url, quality: "1080p"|"720p"|"best"|"audio", outDir? }
     → SSE 진행률 → { filePath, title, durationMs, width, height }

POST /ffmpeg/run         { args: string[], inputPaths: string[], outPath }
     → SSE 진행률 → { outPath, size }

POST /translate          { cues[], sourceLang, targetLang, tone, glossary, mode }
     → SSE 진행률 → { cues: [{ start, end, text, translated }] }

POST /tts/generate       { text, refAudioPath, refText, emotion }
     → SSE 진행률 → { wavPath }

POST /fs/pick-folder     {} → { path }          (네이티브 폴더 선택)
POST /fs/open-folder     { path } → { ok }      (탐색기 열기)
POST /fs/save            { fromOpfsPath, toPath } → { path }
```

### 배포 형태
1. **1순위**: `npx editon-helper` — Node 사용자는 설치 없이 바로 실행
2. **2순위**: Windows `.exe` 단일 파일 (pkg/nexe로 번들, ffmpeg·yt-dlp 포함)
3. 로컬 LLM/TTS는 **Ollama 등 기존 런타임에 위임**한다. 사이드카가 모델을 직접 품지 않는다. (용량·유지보수 부담)

## 5. 다시 한번 솔직하게 — 브라우저의 한계

두팔 스튜디오와 **완전히 똑같이** 만들 수는 없다. 아래는 사이드카를 붙여도 남는 차이다.

| 항목 | 차이 | 영향 |
|---|---|---|
| 처리 속도 | 사이드카 ffmpeg는 네이티브급이지만, 사이드카 없으면 5~10배 느림 | 큼 |
| 영상 길이 | 브라우저 메모리상 1080p 20분이 현실적 상한 | 큼 |
| 설치 경험 | 두팔은 exe 하나, 우리는 "웹앱 + 선택적 도우미" 2단계 | 중 |
| 파일 경로 | 사이드카 없으면 임의 폴더 저장 불가 | 중 |

### 그럼에도 웹앱이 나은 점
- 설치 없이 링크만으로 바로 사용 (사이드카 없이도 편집 기능 대부분 동작)
- Windows/Mac/Linux 구분 없음
- 업데이트가 즉시 반영됨 (v263 같은 버전 관리 불필요)
- 영상이 PC 밖으로 나가지 않는 것은 동일

**결론**: 사이드카를 "설치하면 더 빨라지고 기능이 늘어나는 선택지"로 두고, 웹앱 단독으로도 충분히 쓸 만하게 만드는 것이 이 제품의 정체성이다.
